[Herman] Using static values often hides issues, so seeing how a shader behaves with a spread of values is very valuable. For example, you may not know where a good place for a threshold is, or how the shader behaves in extremes. The simplest way is to allow the user to change the value in the inspector or with in-game UI.
[Herman] In some cases you may not have your hands free to adjust the slider, in which case you can animate it using the time variable instead. The orange mark at the bottom shows the current threshold.

Frame Debugger
[Herman] In complex setups, the final render may involve several passes and multiple shaders. In this case you want to see that the right things happen, and in the right order. Unity’s Frame Debugger is the tool for this. It allows you to see the output of different passes. The Frame Debugger also shows the different maps that serve as input for shaders, such as the shadow map.

Little code tricks

[Sara] Ahora, antes de terminar, quisiera dar unos trucos rápidos para hacer más fácil el desarrollo de shaders y ahorrar algo de tiempo.
[Sara] Usa constantes antes que uniforms. Agregar un uniform a la pipeline es costoso en tiempo e implica también modificar la parte de CPU. Puedes aprovechar el hot reloading para cambiar la variable, o el tiempo como vimos antes.
[Sara] Usar colores fijos, gradientes o texturas de debug como las de mapas UV, para primero testear que el espacio y las zonas objetivo están como esperas.
RuidoSeno
[Sara] Usar ondas sinusoidales deterministas con la misma frecuencia que un ruido, para no tener que usar una textura o algoritmo de ruido durante el desarrollo. En la demo, arriba está el ruido y abajo el seno con la misma frecuencia.
